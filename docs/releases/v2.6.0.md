# Release v2.6.0 — 2026-11-20

Curriculum as Code identity in the code: the canonical CLI is now **`cac`**,
`osn` stays as an identical alias, and the private package is renamed to
**`curriculum-as-code`**. The release also completes the draft module series of
`sma-coding` tracks A and B (154 modules, so 753 modules for six programmes,
all `draf`) and applies two syllabus patch revisions (`sma-coding` v1.4.1,
`tk-coding` v1.0.3). The tag `v2.6.0` marks this release. This is a **minor**
release: **no breaking changes**,
and **no curriculum content transcribed from a syllabus changed** by the
identity work (`data/`, `src/schema/` and `src/domain/` are byte-identical
before and after #251-#255).

This document only covers what changed between v2.5.0 and v2.6.0; for earlier
releases read [`v2.5.0.md`](v2.5.0.md).

## Why minor

`docs/migrations/2026-11-cac-cli-contract.md` section 5.3 and the owner's
Gate 9 decisions (K1-K7, 2026-11-20, recorded in
`docs/migrations/2026-11-cac-gate9-review.md`): adding a command name and
renaming a private, unpublished package are additive for every documented
consumer, so they are **minor**. Removing the `osn` alias, or changing what
it prints, would be **major**.

Result (2026-11-20, owner decision "full release now"): `bun run version`
consumed 23 changesets (3 `minor`, 20 `patch`) and moved `package.json`
`version` from `2.5.0` to **`2.6.0`**. The three `minor` entries are
`cac-bin-alias-osn`, `paket-curriculum-as-code` and
`cac-platform-identity-preparation`; the rest are `patch`.

## Upgrade notes

### From `osn` to `cac`

| You use | In v2.6.0 | What to do |
| --- | --- | --- |
| `osn <command> ...` (`bun src/cli/index.ts`, `bun run validate`, `bun run privacy-check`) | Unchanged, byte for byte: same commands, flags, `--json`, exit codes, and the `osn` prefix in messages | Nothing. Move to `cac` when convenient |
| `cac <command> ...` (`bun src/cli/cac.ts`, `bin.cac`) | New canonical name; identical behaviour | Use it in new scripts and documentation |
| Text that parses messages | `cac` prints `cac validate: ...`; `osn` still prints `osn validate: ...` | Match on the name you invoke, or use `--json` |
| Global help | `cac --help` has its own title and two notes (alias, non-affiliation); `osn --help` is unchanged | Nothing |
| Saved Markdown artefacts | Titles such as `# osn plan:` and `# osn checklist:` are unchanged for both names (K5) | Nothing |

**Alias guarantee (K2, K3, K4).** `osn` prints no deprecation warning. It is
removed only in a **major** release, at the earliest **six months after the
removal is announced**, and only when no active consumer still depends on it.
Until then its output is locked by the contract tests in
`tests/integration/cli-contract.test.ts` (CLI-C-01..13 for both names).

### Package name

`package.json` `name` changes from `kurikulum-informatika` to
`curriculum-as-code`, together with `bun.lock` and `packageInfo.name` in
`src/index.ts`. The package stays `private: true` and is not published.
Code that compares `packageInfo.name`, or tooling that reads the workspace
name from the lockfile, must use the new name. `--version` still prints the
SemVer of the software; every programme keeps its own `syllabusVersion`
(ADR-0005).

### What does not change

- The programme id `osn`, `data/osn/`, its syllabus source and the
  non-affiliation notice (not official Puspresnas / IA TOKI / IOI material).
- The repository is still `ahliweb/osn`. The rename to `ahliweb/cac` is a
  separate step (F3) that waits for Gate 15 and the owner's explicit
  permission; links and `git clone` instructions keep the current address
  until then.

## What is new

- **CLI `cac`** with `osn` as alias in one core (#251).
- **Package `curriculum-as-code`** (#252).
- **Documentation** writes `cac` as the canonical command and describes the
  alias policy: README, AGENTS, CLI reference, guides per role, governance
  (#253).
- **Contract tests** for both CLI names, every programme, and registry
  invariants (#254).
- **Requirements** `IDENTITY-CAC-001..010` registered and checked by
  `check:requirements`; CI runs `validate` with both names and runs
  `check:requirements` (#255).
- **Migration preparation documents** (F1, #152-#157): consumer inventory,
  CLI contract, invariants, security and recovery, Gate 9 review, final
  runbook.
- **154 learning modules** for `sma-coding` tracks A (77) and B (77), all
  `draf` (#237): `sma-coding` has 393 modules and the six programmes 753. The
  design is in `docs/programs/sma-coding/rancangan-modul-ab.md`. Track B uses
  `awcms-one` only as a case study of the `landing` profile.
- **`check:module-code` checks `ts` and `js`** fenced blocks with
  `Bun.Transpiler` (syntax only, no type check, nothing run; a block marked
  `setengah-jadi` is skipped and counted).
- **Syllabus patches**: `sma-coding` v1.4.1 (legal-basis wording aligned with
  UU 1/2023, #238) and `tk-coding` v1.0.3 (objective 4 without "belok kanan",
  #239). Week codes and the CP mapping are unchanged.
- **Review notes verified** (#125): points of
  `docs/programs/catatan-tinjauan-modul.md` checked against official sources;
  the rest stays for a human reviewer.
- **Release notes** (this document, #256).
