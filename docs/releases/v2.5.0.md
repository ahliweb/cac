# Release v2.5.0 — 2026-11-19

Learning modules for every coding programme. The six programmes
(`tk-coding`, `sd-coding`, `smp-coding`, `sma-coding`, `kuliah-coding`,
`dewasa-coding`) now have a learning-module index and 599 modules in total.
The release also aligns the bridges between neighbouring programmes, verifies
the sources of two regulations, and adds automatic checks for the code in
modules and the pictures in learner sheets.

This is a **minor** release with **no breaking changes**. **No OSN curriculum
content changed.** **Every module is a draft:** all 599 have status `draf`,
and the owner has approved none of them.

This document only covers what changed between v2.4.0 and v2.5.0. Read
[`docs/releases/v2.4.0.md`](v2.4.0.md) for the previous release.

## Upgrade notes

None required. Run `bun install` after pulling the tag.

These things behave differently:

- **`bun run check:module-code` checks more.** Besides `cpp`, it now
  compiles `arduino` blocks (`g++ -std=c++17 -fsyntax-only` against the mock
  `scripts/fixtures/arduino-mock/Arduino.h`; syntax and types only, not
  board behaviour) and parses `python` blocks (`python3 -I`, `ast.parse`;
  syntax only). A block whose info string carries `setengah-jadi` (for
  example ```` ```cpp setengah-jadi ````) is skipped and counted. Blocks
  indented inside a list item are dedented before the check. The command
  fails if `g++` or `python3` is missing.
- **`bun run check:learner-assets` is new.** It checks
  `content/<program>/gambar/*.svg` (well-formed, `viewBox`, no script,
  raster, `foreignObject`, `on*` attribute, external link, `data:` URI or
  `@import`, at most 50 KB) and the image links in
  `content/<program>/lembar/*.md`. An unreferenced SVG is a warning. It
  fails (error, not warning) when a module or sheet body starts with its own
  `# ` title, because `render modul` prints the title from the index.
- **`osn render modul --program <id>` works for six programmes.** It needs
  that programme's `data/<id>/modules.json`; `--lembar` renders the child's
  learner sheet for `tk-coding` and `sd-coding` only. Other uses exit `2`.
- **`osn validate` checks more.**
  - A module of `sma-coding` track D or E (id starting `d-` or `e-`, or a
    week of a track with `cpStatus` `pengayaan`) must have an empty
    `cpItems`, because enrichment never counts as covering a CP item.
  - A cross-programme code check (ADR-0010) reports a week, course or module
    code named in a bridge file that does not exist in its source corpus.
  - Each programme's `modules.json` is checked against its own schema.
- **Syllabus versions moved.** `sma-coding` 1.4.0, `tk-coding` 1.0.2,
  `sd-coding` 1.1.0, `smp-coding` 1.2.0, `kuliah-coding` 1.2.0 and
  `dewasa-coding` 1.2.0 (bridge sections only, plus the patch revisions
  from source verification). `data/dewasa-coding` and `data/sma-coding` each
  gained one bridge file, so `osn validate` now reads 8 files for each.
- **Requirements register** has 109 requirements. New ones are `FR-39`..`FR-45`
  and `TR-20`..`TR-22`.

## What is new

### Owner decisions (2026-11-19)

- **Complete modules, one per week, course or syllabus module**, with a
  schema of its own per programme; `tk-coding` and `sd-coding` modules are
  teacher guides with a separate learner sheet for the child (#124).
- **Bridges aligned** with every recommendation K1 to K8 of
  `docs/programs/rancangan-jembatan-antarprogram.md` (#177), among them
  decision 12.7 option A of the `dewasa-coding` syllabus: the
  `kuliah-coding` to `dewasa-coding` track `PRO` bridge with three entry
  profiles and per-module recognition.
- **Source verification** of SK BSKAP 046/H/KR/2025 and Kepmenaker 282/2016
  (see below).
- **Automatic checks** for Arduino and Python examples and for learner
  sheet pictures (#178).

Module bodies live in `content/<program>/modules/<id>.md`. Design documents
for each series are in `docs/programs/<id>/rancangan-modul*.md`;
`docs/programs/catatan-tinjauan-modul.md` lists what a human reviewer should
check. The 29 earlier `sma-coding` modules also got a scientific review
(#125), with two draft reports in
`docs/programs/sma-coding/tinjauan-modul/`; they stay `draf`.

### Bridges between programmes

Five bridge pairs were applied in order: `kuliah-coding` to `dewasa-coding`
`PRO`, `sma-coding` to `kuliah-coding` (recognition per CPMK), `smp-coding`
and `sma-coding` (placement in the grade-X foundation block), `sd-coding`
and `smp-coding`, and `tk-coding` to `sd-coding`. Bridges are now data the
code checks: `data/dewasa-coding/kuliah-bridge.json` and
`data/sma-coding/smp-bridge.json` are new, and the others were updated.

### Source verification

- **SK BSKAP 046/H/KR/2025.** The origin of the copy is verified; the CP
  quotations in `data/sd-coding/cp-elements.json` and the CP KKA Phase D in
  `data/smp-coding/cp-elements.json` match word for word (4 of 4 each). A
  counterpart on the JDIH site was not found and stays marked unverified.
- **Kepmenaker 282/2016.** The official attachment was downloaded and the 47
  unit codes and titles were matched; one title spelling was corrected
  (unit `J.620100.047.01`). The schema gained the value
  `judul-cocok-lampiran-resmi`. The code suffixes stay unverified because
  the attachment is inconsistent between its parts.

### Code and requirements

- Module-index schemas per programme (`src/schema/tk-module.ts`,
  `sd-module.ts`, `smp-module.ts`, `kul-module.ts`, `dw-learning-module.ts`)
  and the cross-programme code check (ADR-0010, `TR-22`).
- CI gained steps for `python3` and `check:learner-assets`.
- The real `g++` tests have a 30 second timeout.
