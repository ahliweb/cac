# Release v2.0.0 — 2026-11-18

Multi-programme restructure, learner sheets and learning modules. This is a
**major** release because the corpus paths, the package name and one CLI
output shape changed. **No curriculum content changed** — the OSN corpus is
byte-identical to v1.1.0, only moved.

If you are adopting this project for the first time, read
[`docs/releases/v1.0.0.md`](v1.0.0.md) first; this document only covers what
moved between v1.1.0 and v2.0.0.

## Upgrade notes

Breaking changes, all from the multi-programme restructure
([ADR-0006](../architecture/adr/0006-multi-program-repository.md), #50, #57):

| Before (v1.1.0) | After (v2.0.0) |
| --- | --- |
| `data/*.json` | `data/osn/*.json` |
| `data/samples/` | `data/osn/samples/` |
| package `osn-informatika-2026` | package `kurikulum-informatika` |
| `osn validate --json` → single-programme object | without `--program`: `{ ok, programs: [...] }` |

- **Paths.** Any script, tool or document that reads the old `data/` paths
  must be updated. File contents are unchanged.
- **Package name.** Update any dependency or workspace reference. The `osn`
  binary keeps its name, so command lines do not change.
- **`osn validate --json`.** Without `--program` the command now validates
  every registered programme and emits `{ ok, programs: [...] }`. With
  `--program <id>` it emits `{ ok, program, findings, summary }`. Consumers
  parsing the old shape must adapt. Exit codes are unchanged.
- **Default programme.** `--program` defaults to `osn`, so `plan`, `render`,
  `report` and `checklist` behave as before without the flag.

Run `bun install` after pulling the tag.

## What is new

### Programme registry and `--program`

`data/programs.json` (schema `src/schema/program.ts`) registers each
programme: kebab-case unique id, `corpusDir` = `data/<id>`, source document,
and `syllabusVersion` / `syllabusDate`. `osn validate` checks the registry
and that the registered version and date equal the corpus files'. Today only
`osn` is registered (syllabus `2.0`, `2026-09-04`).

`osn validate`, `plan`, `render`, `report` and `checklist` accept
`--program <id>`; an unknown programme is a usage error (exit 2).
`osn privacy-check` still scans all of `data/` recursively.

### Learner sheet

```sh
osn render lembar-siswa --week <1-28> [--out <path>] [--force] [--program <id>]
```

Renders an Indonesian sheet for students: the week's focus and outcome, the
topic families it exercises, the practice target and mini-contest marker, the
phase-gate evidence when a gate follows, the §5.3 hint-policy callout
verbatim, a blank self-check list, the cited references and a source footer.
Derived only from the validated corpus, deterministic, and free of
learner-identity fields (ADR-0004).

### Learning modules

- Optional per-programme index `data/<program>/modules.json` (schema
  `src/schema/module.ts`), with Markdown bodies under the new top-level
  `content/<program>/modules/`.
- `osn render modul --id <id> [--out] [--force] [--program]` puts a
  `DRAF`/`DITARIK` banner after the title unless the module is `disetujui`.
- `osn validate` also checks a programme's module index (schema, topic
  family, week and reference ids, body file exists and is non-empty).
- `bun run check:module-code`, also a CI step, compiles every `cpp` block with
  `g++ -std=c++17 -fsyntax-only` without running anything, and fails when
  `g++` is missing.
- Pilot module `dasar-pemrograman` (weeks 1-2, references R1).

### Architecture decisions

- **ADR-0006** — multi-programme repository: registry, one corpus per
  programme, `--program` selector, package rename.
- **ADR-0007** — authored learning content kept apart from the transcribed
  corpus, with a `draf` → `ditinjau` → `disetujui` lifecycle that only a human
  can complete.

### Draft SMA coding syllabus (not yet data)

`docs/programs/sma-coding/` holds a draft for grades X (Fase E) to XII
(Fase F): a C++ track bridging to the ten OSN topic families and a web track
in JavaScript/TypeScript on Bun ending with the public `awcms-one` template.
CP Informatika passages are quoted verbatim from the official 2025 subject
guide; the rest is authored content marked `DRAF`. It is **not** registered in
`data/programs.json` and is not a data source. Owner decisions recorded: the
web track uses `awcms-one` option 1, and C++-track topics beyond the CP are
optional enrichment.

### Maintenance

- Dependencies updated within their current major (zod 4.6.7,
  `@changesets/cli` 3.0.3, `@types/bun` 1.4.4); Biome stays on 2.5.x because
  2.6 would format Markdown and reformat every document.
- Bun pinned at 1.4.4 in CI. Bun 1.4.4 counts lines slightly differently,
  which put `scripts/check-checklist-fidelity.ts` just under the 85% per-file
  gate; tests for two error paths fix this without lowering the threshold.

## Content status

The pilot module `dasar-pemrograman` and the SMA draft are **authored
content, status `DRAF`**. Neither has been reviewed or approved by the owner,
and the module renderer marks it as a draft accordingly. Approval is a human
step (ADR-0007) and is not part of this release.

## Still open

Unchanged from v1.0.0 and v1.1.0, and still true:

- Contact placeholders in `SECURITY.md`, `CODE_OF_CONDUCT.md`,
  `docs/governance/privacy.md` and `docs/governance/incident-response.md`
  must be filled before publication.
- The seeded syllabus-check entry records transcription provenance only; no
  live check of the external OSN/IOI sources has been performed.
- `osn report --by topic|week` exits 2 pending a problem-to-topic resolver
  the corpus cannot supply.
- `complexitySelectionAccuracy` is a TLE-based proxy, not a direct
  measurement.
- The week-to-topic-family mapping is an editorial inference, not source
  text.
