Modul ini untuk murid kelas X jalur B (Web dengan JavaScript, TypeScript, dan Bun), minggu `B-X2-M12` silabus v1.4.1: Git dan kolaborasi dasar. Prasyarat: modul `b-x2-m11` (mesin pencari dan dokumentasi) dan `b-x1-m8` (lingkungan kerja, termasuk `git init`, `add`, `commit`, dan `log`).

Modul ini berstatus DRAF: karangan penyusun, belum ditinjau pemilik. Butir `E-LD-f` (media digital untuk produksi dan diseminasi konten, partisipasi, kolaborasi) dipetakan silabus sebagai dipenuhi jalur ini; modul draf ini belum dihitung sebagai pemenuhan butir itu.

Semua contoh dijalankan penyusun dengan Git 2.43.0 dan Bun 1.4.4 per 2026-11; pesan Git di komputermu bisa sedikit berbeda. **Tidak ada akun, tidak ada layanan luar, dan tidak ada yang dikirim ke internet.** Kolaborasi disimulasikan dengan folder di komputermu yang berperan sebagai repositori pusat. Nama dan surel di contoh karangan (`@contoh.example`); di kelas pakai nama yang ditentukan gurumu, bukan surel pribadi. Tugas baca-dan-prediksi ditandai `AI: tanpa AI`; selain itu AI generatif boleh dipakai dengan etika dan dicatat, tanpa data pribadi, kata sandi, atau tugas bernilai pada permintaanmu.

## Prediksi dulu

Ini tugas baca-dan-prediksi, `AI: tanpa AI`. **Tebak dulu, tulis jawabanmu, baru jalankan.** Urutan perintah ini dijalankan di folder kosong. `git switch -c cabang` membuat cabang baru dan langsung berpindah ke sana; `--no-edit` memakai pesan gabungan bawaan.

```sh

git switch main

git commit -m "Tambah c.js"

git log --oneline --graph
ls
```

2. Berkas apa saja yang ada di folder pada akhirnya?

## Contoh terselesaikan

Pada percobaan penyusun, keluaran perintah terakhir (kode di depan pesan commit berbeda di komputermu):

```text
*   6cb83d7 Merge branch 'cabang'
|\  
| * 641e8d7 Tambah b.js
* | c580c83 Tambah c.js
|/  
* f0e0075 Tambah a.js
```

`ls` menampilkan `a.js`, `b.js`, dan `c.js`. Karena `main` dan `cabang` sama-sama punya pekerjaan baru, Git membuat satu commit gabungan dengan dua induk. Bila `main` tidak punya pekerjaan baru, Git cukup menggeser `main` maju (*fast-forward*) tanpa commit gabungan. Menurut dokumentasi `git branch`, membuat cabang tidak berpindah ke sana; `git switch` yang berpindah.

**Kolaborasi dengan repositori pusat.** Dua murid karangan, Dewi dan Budi, berbagi satu repositori pusat. `git init --bare` membuat repositori tanpa folder kerja (menurut dokumentasi `git init`, isinya langsung di folder itu); itu bentuk yang cocok untuk pusat yang hanya dikirimi dan diambil. Di sini `pusat.git` hanyalah folder di komputer. Dewi mulai:

```sh
git init --bare -b main pusat.git
git clone pusat.git dewi
cd dewi
git config user.name "dewi-contoh"
git config user.email "dewi-contoh@contoh.example"
printf 'const nama = "dunia";\nconsole.log("Halo, " + nama);\n' > salam.js
git add salam.js
git commit -m "Skrip salam pertama"
git push -u origin main
```

Keluaran bagian utamanya (alamat folder diringkas menjadi `...`):

```text
Initialized empty Git repository in .../pusat.git/
Cloning into 'dewi'...
warning: You appear to have cloned an empty repository.
done.
[main (root-commit) 7872cce] Skrip salam pertama
 1 file changed, 2 insertions(+)
 create mode 100644 salam.js
To .../pusat.git
 * [new branch]      main -> main
branch 'main' set up to track 'origin/main'.
```

`clone` menyalin repositori beserta riwayatnya, `push` mengirim commit ke pusat. Lalu Budi mengambil salinan sendiri, membuat cabang untuk pekerjaannya, dan mengirim cabang itu:

```sh
cd ..
git clone pusat.git budi
cd budi
git config user.name "budi-contoh"
git config user.email "budi-contoh@contoh.example"
git switch -c fitur-nama
sed -i 's/"dunia"/"kelas X"/' salam.js
git commit -am "Salam untuk kelas X"
git push -u origin fitur-nama
```

Sementara itu Dewi, di cabang `main`, mengubah **baris yang sama**, lalu mengirimnya, mengambil cabang Budi, dan mencoba menggabungkan:

```sh
cd ../dewi
sed -i 's/"dunia"/"teman"/' salam.js
git commit -am "Salam untuk teman"
git push
git fetch
git merge origin/fitur-nama
cat salam.js
git status --short
```

Keluaran dua perintah terakhir yang penting:

```text
Auto-merging salam.js
CONFLICT (content): Merge conflict in salam.js
Automatic merge failed; fix conflicts and then commit the result.
<<<<<<< HEAD
const nama = "teman";
=======
const nama = "kelas X";
>>>>>>> origin/fitur-nama
console.log("Halo, " + nama);
UU salam.js
```

Itu **konflik**: dua orang mengubah baris yang sama dengan cara berbeda, dan Git tidak mau memilih sendiri. Menurut dokumentasi `git merge`, bagian antara `<<<<<<<` dan `=======` adalah sisimu (`HEAD`), bagian sesudahnya adalah sisi yang masuk. `UU` di `git status --short` berarti kedua sisi mengubah berkas itu. Menyelesaikannya keputusan manusia: sunting berkas ke hasil yang diinginkan, **buang ketiga tanda**, lalu `git add` dan `git commit`.

```sh
printf 'const nama = "teman kelas X";\nconsole.log("Halo, " + nama);\n' > salam.js
git add salam.js
git commit -m "Gabung: salam untuk teman kelas X"
git push
git log --oneline --graph --all
```

```text
[main 7813402] Gabung: salam untuk teman kelas X
To .../pusat.git
   b939ed8..7813402  main -> main
*   7813402 Gabung: salam untuk teman kelas X
|\  
| * 0640518 Salam untuk kelas X
* | b939ed8 Salam untuk teman
|/  
* 7872cce Skrip salam pertama
```

Budi memperbarui salinannya dengan `git switch main` lalu `git pull`; menurut dokumentasi `git pull`, perintah itu menjalankan `git fetch` lalu memasukkan hasilnya ke cabang saat ini. Pada percobaan penyusun, `git pull` memberi `Fast-forward`, riwayat Budi sama dengan Dewi, dan `bun run salam.js` mencetak `Halo, teman kelas X`.

## Kesalahan umum

- **Mengira `git push` selalu berhasil.** Bila pusat sudah punya commit yang belum kamu punya, Git menolak: `! [rejected] main -> main (fetch first)`. Ambil dulu dengan `git pull`, selesaikan bila konflik, lalu kirim lagi.
- **`git pull` berhenti dengan `fatal: Need to specify how to reconcile divergent branches`.** Ini terjadi pada percobaan penyusun saat riwayatmu dan pusat sama-sama punya commit baru. Git meminta memilih merge, rebase, atau hanya fast-forward; tanyakan gurumu, mis. `git pull --no-rebase` untuk merge.
- **Meninggalkan tanda konflik di berkas.** `<<<<<<<`, `=======`, dan `>>>>>>>` bukan JavaScript yang sah; `bun run` akan gagal. Buang ketiganya dan jalankan skripnya sebelum `git add`.
- **Lupa berpindah cabang.** `git branch fitur-x` membuat cabang tetapi tidak berpindah; pakai `git switch fitur-x` atau `git switch -c fitur-x`. Periksa dengan `git branch`.
- **Menaruh rahasia atau data nyata di repositori.** Riwayat Git menyimpan semuanya.

## Kunci dan petunjuk

**Ingat kembali.** 1: contoh: `javascript tambah nol di depan angka`; menyebut bahasa dan hal yang dicari mempersempit hasil. 2: sangat sedikit pada data yang sudah (hampir) terurut, paling banyak pada data terbalik. 3: `<head>` memuat keterangan tentang dokumen yang tidak tampil di halaman (misalnya `meta` dan `title`); `<body>` memuat isi yang tampil.

**Prediksi dulu.** 1: empat baris (`Tambah a.js`, `Tambah b.js`, `Tambah c.js`, dan satu commit `Merge branch 'cabang'`); ya, ada commit gabungan karena kedua cabang punya pekerjaan baru. 2: `a.js`, `b.js`, `c.js`.

**Contoh setengah jadi.** Isi berurutan: `switch`, `-m`, `push`. Perintahnya: `git switch -c fitur-judul`, `git commit -am "Tambah judul"` (`-a` dan `-m` boleh digabung), `git push -u origin fitur-judul`.

**Soal Parsons.** Urutan benar: c, b, d, e, a, f. Konflik harus diselesaikan (d) sebelum `git add` (e) dan commit gabungan (a); `push` terakhir.

**Latihan.** 1: Git menggeser `main` maju (`Fast-forward`) tanpa commit gabungan; riwayat lurus tiga commit tanpa cabang. 2: contoh urutan: Dewi dan Budi masing-masing `git switch -c cabang-sendiri`, mengubah baris yang berbeda, `git commit -am`, `git push -u origin cabang-sendiri`; lalu salah satu `git fetch`, `git merge origin/cabang-lawan`, `git push`. Periksa `git log --oneline --graph --all`. 3: tiga langkah: (1) buka berkas konflik dan putuskan hasil akhirnya, buang tanda; (2) `git add` berkas itu; (3) `git commit`. 4: contoh: `Ubah salam menjadi "teman kelas X"`, `Tambah komentar di salam.js`, `Perbaiki tanda kutip pada baris nama`; jawaban lain diterima bila menjelaskan isi.

**Latihan bercampur.** 1: contoh: `git add urut.js`, `git commit -m "Bubble sort"`, `git switch -c insertion`, ganti isi, `git commit -am "Insertion sort"`, `git switch main`, `git merge insertion`; bila konflik, selesaikan seperti di contoh. 2: dokumentasi `git branch` (`https://git-scm.com/docs/git-branch`) menjelaskan `git branch -d`, yang hanya menghapus cabang yang sudah digabung, dan `-D` yang memaksa. Contoh dijalankan penyusun: `git branch -d cabang` memberi `Deleted branch cabang (was 641e8d7).` setelah penggabungan.

**Ulang berjarak.** 1: `git switch -c fitur-x`; cabang memisahkan pekerjaan baru dari `main` sampai siap digabung. 2: terjadi konflik; sunting berkas, buang tanda, `git add`, lalu `git commit`. 3: `fetch` hanya mengambil riwayat baru; `pull` menjalankan `fetch` lalu memasukkan hasilnya ke cabang saat ini.
