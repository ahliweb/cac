Keluaran:

Fungsi **rekursif** memanggil dirinya sendiri untuk masalah yang lebih kecil. Ia selalu punya dua bagian. **Kasus dasar** adalah masalah yang cukup kecil untuk dijawab langsung tanpa memanggil diri (di sini `n <= 1` menghasilkan 1). **Langkah rekursif** mengubah masalah menjadi satu atau lebih masalah yang lebih kecil dan memanfaatkan jawabannya (`n * fak(n - 1)`). Tanpa kasus dasar, pemanggilan tidak pernah berhenti.

Tiap pemanggilan punya salinan `n` sendiri. Komputer menaruh pemanggilan yang sedang berjalan di **tumpukan pemanggilan**, persis seperti tumpukan di modul `a-x2-m7`: yang terakhir dipanggil (`fak(1)`) selesai lebih dulu, lalu `fak(2)`, lalu `fak(3)`. Itu sebabnya baris `keluar` muncul dari yang terkecil. Tumpukan ini berukuran terbatas; rekursi yang terlalu dalam atau tanpa kasus dasar membuat program berhenti dengan galat karena tempat habis. Program berikut menghitung faktorial dari masukan; `long long` dipakai karena faktorial tumbuh cepat.

```cpp
#include <iostream>
using namespace std;

long long fak(int n) {
  if (n <= 1) {
    return 1;
  }
  return n * fak(n - 1);
}

int main() {
  int n;
  cin >> n;
  cout << n << "! = " << fak(n) << "\n";
}
```

Masukan (`masukan.txt`):

```text
5
```

Keluaran:

```text
5! = 120
```

Contoh kedua: deret Fibonacci, dengan `fib(0) = 0`, `fib(1) = 1`, dan tiap suku berikutnya jumlah dua suku sebelumnya. Rumusnya langsung menjadi program, dengan dua kasus dasar dan dua pemanggilan rekursif. Program berikut juga menghitung banyak pemanggilan fungsi, lewat parameter `panggilan` yang bertanda `&`.

```cpp
#include <iostream>
using namespace std;

int fib(int n, long long& panggilan) {
  panggilan++;
  if (n < 2) {
    return n;
  }
  return fib(n - 1, panggilan) + fib(n - 2, panggilan);
}

int main() {
  int daftar[3] = {10, 20, 30};
  for (int k = 0; k < 3; k++) {
    long long panggilan = 0;
    int hasil = fib(daftar[k], panggilan);
    cout << "fib(" << daftar[k] << ") = " << hasil << ", " << panggilan << " panggilan\n";
  }
}
```

Keluaran:

```text
fib(10) = 55, 177 panggilan
fib(20) = 6765, 21891 panggilan
fib(30) = 832040, 2692537 panggilan
```

Hasilnya benar, tetapi `n` yang naik dari 20 ke 30 membuat panggilan naik dari 21.891 menjadi 2.692.537, jauh lebih dari kenaikan `n`. Penyebabnya: `fib(n - 1)` dan `fib(n - 2)` menghitung ulang suku-suku yang sama berkali-kali. Cara yang ditulis dengan perulangan hanya perlu sekitar `n` langkah untuk hasil yang sama. Rekursi bukan lebih baik atau lebih buruk secara umum; ia cocok bila masalah memang terpecah menjadi masalah serupa yang lebih kecil dan tidak bertumpang tindih. Modul `matkom-induksi-dan-rekursi-matematis` membahas rekursi dari sisi matematika, dan `a-x2-m12` membahas cara menghitung langkah.

## Kesalahan umum

- **Lupa kasus dasar.** Fungsi memanggil dirinya tanpa henti sampai tempat di tumpukan pemanggilan habis dan program berhenti dengan galat.
- **Langkah rekursif tidak mengecilkan masalah.** Memanggil `fak(n)` dari dalam `fak(n)` tidak pernah mencapai kasus dasar. Argumen harus bergerak menuju kasus dasar, misalnya `n - 1`.

- **Mengira rekursi selalu lebih cepat atau lebih ringkas.** Fibonacci rekursif sederhana menghitung ulang suku yang sama; versi perulangan jauh lebih hemat.

## Kunci dan petunjuk

**Ingat kembali.** 1: bagian kiri `v[0..i]` sudah terurut (belum tentu final). 2: karena `tengah` sudah diperiksa dan bukan jawaban; menggesernya melewati `tengah` memastikan daerah pencarian mengecil di tiap putaran, sehingga perulangan pasti berhenti. 3: tabel `b` kali `k` menjadi `k` kali `b`; bentuknya berbeda, sehingga isinya tidak muat di array yang sama tanpa saling menimpa. 4: `return` mengirim nilai kembali dan mengakhiri fungsi; variabel yang dibuat di dalam fungsi hanya hidup selama fungsi berjalan dan hilang setelah selesai.

**Prediksi dulu.** 1: urutan keluaran seperti di contoh. 2: `fak(1)`, karena ia dipanggil paling akhir dan tidak menunggu pemanggilan lain; `fak(3)` baru bisa selesai setelah `fak(2)` selesai, yang menunggu `fak(1)`.

**Latihan bercampur.** 1: program contoh; kasus dasar pertama untuk daerah kosong, kasus dasar kedua untuk ketemu:

```cpp
#include <iostream>
#include <vector>
using namespace std;

int cariBiner(vector<int>& v, int x, int kiri, int kanan) {
  if (kiri > kanan) {
    return -1;
  }
  int tengah = kiri + (kanan - kiri) / 2;
  if (v[tengah] == x) {
    return tengah;
  }
  if (v[tengah] < x) {
    return cariBiner(v, x, tengah + 1, kanan);
  }
  return cariBiner(v, x, kiri, tengah - 1);
}

int main() {
  vector<int> v = {1, 4, 6, 9, 12};
  int n = v.size();
  cout << cariBiner(v, 9, 0, n - 1) << " " << cariBiner(v, 5, 0, n - 1) << "\n";
}
```

Keluaran:

```text
3 -1
```

2: tumpukan dari bawah ke atas: `main`, `fak(3)`, `fak(2)`, `fak(1)`; `fak(1)` di puncak dan menjadi yang pertama selesai. Itu LIFO: yang terakhir masuk keluar lebih dulu, sama seperti `top()` pada `stack`.

**Ulang berjarak.** 1: kasus dasar (masalah kecil yang dijawab langsung) dan langkah rekursif (memanggil diri untuk masalah yang lebih kecil). 2: pemanggilan tidak pernah berhenti, dan tiap pemanggilan menambah satu bingkai di tumpukan pemanggilan yang berukuran terbatas; akhirnya tempat habis dan program berhenti dengan galat. 3: karena `fib(n - 1)` dan `fib(n - 2)` menghitung ulang suku yang sama berkali-kali; `fib(30)` memerlukan 2.692.537 panggilan.
