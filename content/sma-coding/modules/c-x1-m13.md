## Untuk siapa modul ini

Modul ini untuk murid kelas X jalur C (IoT dan robotika), minggu `C-X1-M13` silabus v1.3: proyek mini kelas X semester 1. Prasyarat: modul `c-x1-m12` (fungsi dan array) dan semua modul `c-x1-m8` sampai `c-x1-m12`.

Modul ini berstatus DRAF: karangan penyusun, belum ditinjau pemilik. Ia mendukung butir `E-BK-d` (solusi program sederhana dalam format pseudocode) dan tidak dihitung memenuhi butir capaian pembelajaran mana pun. Penilaian proyek memakai rubrik dari gurumu; modul ini tidak menilai.

Ada dua cara mengerjakan. **Dengan papan (F):** kelompok tiga murid merakit satu sensor dan satu aktuator. **Tanpa papan:** kamu menulis rancangan, pseudocode, dan program, lalu mengujinya dengan "papan tiruan" di komputer memakai nilai sensor buatan. Pilihan proyek: lampu malam otomatis atau alarm tombol.

## Keselamatan perangkat

- Daya hanya dari kabel USB. Tidak ada listrik jaringan (220 V) dan tidak ada baterai pada modul ini.
- Cabut kabel USB sebelum memasang atau melepas sensor, tombol, LED, atau buzzer. Periksa polaritas LED dan buzzer sebelum menyalakan.
- Hanya komponen dan resistor yang disiapkan guru; sensor disambung ke pin yang ditunjuk lembar guru. Batas tegangan pin papanmu `[belum terverifikasi]`.
- Tidak ada solder. Papan percobaan dan kabel jumper sudah cukup.
- Proyek ini **tidak memakai kamera atau mikrofon** dan tidak mengukur tubuh siapa pun. Data yang dicatat hanya nilai sensor ruangan atau keadaan tombol.
- Papan atau komponen yang terasa panas, berbau, atau berasap: cabut kabel dan panggil guru.

## Rencana proyek

Sebelum menyentuh papan, tulis rencanamu: apa arti "selesai", lalu tebakan hasilnya. Bila tebakan dan hasil berbeda, di situlah kamu belajar. Satu halaman cukup, dengan enam bagian: tujuan, diagram I-P-O, pseudocode, kriteria selesai, daftar uji, dan prediksi hasil.

Berikut contoh terselesaikan untuk **lampu malam otomatis**: LED menyala saat ruangan gelap.

| Bagian | Isi contoh |
| --- | --- |
| Tujuan | LED menyala saat ruangan gelap dan padam saat terang. |
| Masukan | Sensor cahaya (nilai 0 sampai 4095 pada contoh; periksa papanmu). |
| Proses | Bandingkan nilai dengan ambang; ambang diukur sendiri (modul `c-x1-m11`). |
| Keluaran | LED. |
| Kriteria selesai | Lampu menyala bila nilai di bawah ambang, padam bila tidak; tiga uji lolos. |
| Prediksi | Nilai 3500: padam. Nilai 400: nyala. Nilai tepat di ambang: padam. |

Pseudocode-nya:

```text
ULANG TERUS:
  baca nilai sensor cahaya
  BILA nilai < AMBANG:
    nyalakan LED
  JIKA TIDAK:
    padamkan LED
  tunggu 200 ms
```

Programnya (nilai sensor kecil berarti gelap pada contoh ini; arah nilai sensormu perlu diukur):

```arduino
// Arduino-C++ untuk ESP32. Diperiksa check:module-code terhadap header tiruan (sintaks dan tipe saja, bukan bukti perilaku papan).
const int PIN_SENSOR = 34;   // contoh; periksa papanmu
const int PIN_LED = 2;
const int AMBANG = 2000;     // ukur sendiri; ini contoh

bool gelap(int nilai) {
  return nilai < AMBANG;
}

void setup() {
  Serial.begin(115200);
  pinMode(PIN_LED, OUTPUT);
}

void loop() {
  int nilai = analogRead(PIN_SENSOR);
  Serial.println(nilai);
  if (gelap(nilai)) {
    digitalWrite(PIN_LED, HIGH);
  } else {
    digitalWrite(PIN_LED, LOW);
  }
  delay(200);
}
```

Daftar uji dijalankan lebih dulu di komputer. Fungsi di bawah sama dengan `gelap()` pada program; empat nilai uji mencakup nilai biasa dan nilai tepat di batas.

```cpp
// C++17 biasa, jalan di komputer. Diperiksa oleh check:module-code.
#include <iostream>

const int AMBANG = 2000;

bool gelap(int nilai) {
  return nilai < AMBANG;
}

int main() {
  const int UJI[] = {3500, 2000, 1999, 400};
  for (int nilai : UJI) {
    std::cout << "nilai=" << nilai << " -> " << (gelap(nilai) ? "nyala" : "padam") << "\n";
  }
}
```

Keluarannya:

```text
nilai=3500 -> padam
nilai=2000 -> padam
nilai=1999 -> nyala
nilai=400 -> nyala
```

Cocokkan dengan prediksimu. Uji ini hanya membuktikan logikanya; sensormu diuji dengan papan.

Pilihan **alarm tombol**: masukannya tombol (`INPUT_PULLUP`), keluarannya buzzer atau LED. Tulis sendiri tujuan, kriteria, dan daftar ujinya: kapan alarm menyala, kapan padam, dan apa yang terjadi bila tombol ditekan lama.

## Kunci dan petunjuk

**Ingat kembali.** 1: fungsi `void` tidak mengembalikan nilai; fungsi `int` mengembalikan bilangan bulat lewat `return`. 2: kamu melihat nilai sebenarnya pada tiap langkah, bukan nilai yang kamu kira. 3: data yang sudah tersebar sulit ditarik kembali.

**Rencana proyek.** Contoh di atas satu jawaban yang mungkin; rencanamu boleh berbeda selama keenam bagian ada dan kriteria selesai dapat diuji. Untuk alarm tombol, contoh kriteria: "buzzer berbunyi selama tombol ditekan dan diam saat dilepas". Uji batas: tombol ditekan sangat singkat dan sangat lama.

**Daftar periksa.** Tidak ada kunci tunggal; guru memeriksa tiap butir dengan rubrik.

**Umpan balik sejawat.** Umpan balik yang baik menunjuk bagian tertentu, menyebut alasan, dan menawarkan langkah yang bisa dikerjakan. "Bagus" saja bukan umpan balik.

**Latihan bercampur.** 1: `if (gelap(nilai) && digitalRead(PIN_TOMBOL) == LOW)`. 2: 2500 x 100 / 4095 = 61,05 menjadi 61. 3: 10.000 / 200 = 50 kali.

**Ulang berjarak.** 1: contoh jawaban: tujuan dan kriteria selesai (juga boleh: diagram I-P-O, daftar uji, prediksi hasil). 2: karena galat paling sering muncul tepat di batas, misalnya `<` yang seharusnya `<=`. 3: papan tiruan hanya memeriksa logika di komputer; rangkaian bekerja berarti sensor, sambungan, dan program benar di papan.
