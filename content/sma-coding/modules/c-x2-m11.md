## Untuk siapa modul ini

Modul ini untuk murid kelas X jalur C (IoT dan robotika), minggu `C-X2-M11` silabus v1.3: sensor jarak dan keputusan (F). Prasyarat: modul `c-x2-m10` (pencarian dan pengurutan data sensor). Kamu juga memakai percabangan dari `c-x1-m9`, `enum` dari `c-x2-m7`, dan gagasan ambang yang diukur dari `c-x1-m11`.

Modul ini berstatus DRAF: karangan penyusun, belum ditinjau pemilik, dan tidak dihitung memenuhi butir capaian pembelajaran mana pun. Keluaran minggu ini: program jarak. Latihan silabusnya: alarm parkir mini.

Ada dua cara mengerjakan. **Dengan papan (F):** kelompok merakit satu sensor jarak dan satu buzzer aktif sesuai lembar guru. **Tanpa papan:** kamu menelusuri program di kertas dan menjalankan "papan tiruan" di komputer yang mengubah waktu gema karangan menjadi jarak dan zona. Sensor jarak pada contoh dibaca lewat pustaka karangan `PustakaJarak` (bukan pustaka sungguhan, hanya contoh netral); lembar guru menyebut pustaka dan sambungan yang dipakai papanmu. Nomor pin dan batas pada contoh hanya contoh `[belum terverifikasi]` untuk papanmu.

## Keselamatan perangkat

- Daya hanya dari kabel USB. Tidak ada listrik jaringan (220 V) dan tidak ada baterai pada modul ini.
- Cabut kabel USB sebelum memasang atau memindahkan sensor dan buzzer. Periksa polaritas buzzer.
- Sebagian modul sensor jarak mengeluarkan sinyal 5 V pada kaki gema, yang dapat merusak pin papan 3,3 V `[belum terverifikasi]`. Sambungkan hanya sesuai lembar guru; jangan menyambung sendiri.
- Tidak ada solder. Papan percobaan dan kabel jumper sudah cukup.
- Modul ini tidak memakai kamera atau mikrofon, dan tidak mengukur tubuh siapa pun; benda uji berupa kardus atau papan.
- Papan atau komponen yang terasa panas, berbau, atau berasap: cabut kabel dan panggil guru.

## Contoh terselesaikan

Sensor jarak ultrasonik memancarkan bunyi dan mengukur berapa lama gemanya kembali. Waktu itu mencakup perjalanan **pergi dan pulang**, sehingga jarak benda = waktu x kecepatan suara / 2. Kecepatan suara di udara bergantung pada suhu udara (NASA Glenn menjelaskan hubungannya); contoh ini memakai kira-kira 343 m/s, atau 0,0343 cm per mikrodetik `[belum terverifikasi]` untuk ruanganmu. Maka waktu 2915 mikrodetik berarti kira-kira 50 cm.

Pembacaan bisa gagal: tidak ada benda di jangkauan, benda terlalu dekat, atau permukaan miring memantulkan bunyi ke tempat lain. Pada pustaka contoh, `bacaMikrodetik` mengembalikan `false` bila gema tidak ada. Itu bukan "jarak 0 cm"; itu "tidak tahu". Maka ada zona `TIDAK_VALID`, dan alarm tidak boleh berbunyi karenanya, seperti `NaN` di `c-x2-m2`.

Batas keputusan ditentukan dari pengukuran: letakkan kardus di 10, 20, 30, dan 50 cm dari penggaris, catat beberapa pembacaan tiap jarak, lalu pilih batas dengan margin dari sebaran yang kamu lihat. Nilai di bawah hanya contoh.

```arduino
// Arduino-C++ untuk ESP32. Diperiksa check:module-code terhadap header tiruan (sintaks dan tipe saja, bukan bukti perilaku papan).
#include "PustakaJarak.h"

const int PIN_PEMICU = 25;                // contoh; periksa papanmu
const int PIN_GEMA = 26;
const int PIN_BUZZER = 27;                // buzzer aktif
const float CM_PER_US = 0.0343f;          // contoh; bergantung suhu udara
const float JARAK_MIN_CM = 2.0f;          // contoh; periksa lembar data sensormu
const float JARAK_MAKS_CM = 400.0f;
const float BATAS_BAHAYA_CM = 20.0f;      // ukur sendiri; ini contoh
const float BATAS_WASPADA_CM = 50.0f;
const unsigned long SELANG_MS = 100;

enum Zona { TIDAK_VALID, AMAN, WASPADA, BAHAYA };

SensorJarak sensor(PIN_PEMICU, PIN_GEMA);
unsigned long mulai = 0;

float cmDariMikrodetik(unsigned long mikrodetik) {
  return mikrodetik * CM_PER_US / 2.0f;
}

Zona zonaDari(float cm) {
  if (cm < JARAK_MIN_CM || cm > JARAK_MAKS_CM) {
    return TIDAK_VALID;
  }
  if (cm < BATAS_BAHAYA_CM) {
    return BAHAYA;
  }
  if (cm < BATAS_WASPADA_CM) {
    return WASPADA;
  }
  return AMAN;
}

void setup() {
  Serial.begin(115200);
  pinMode(PIN_BUZZER, OUTPUT);
  sensor.mulai();
  mulai = millis();
}

void loop() {
  if (millis() - mulai >= SELANG_MS) {
    mulai = millis();
    unsigned long waktu = 0;
    Zona zona = TIDAK_VALID;
    if (sensor.bacaMikrodetik(waktu)) {
      zona = zonaDari(cmDariMikrodetik(waktu));
    }
    digitalWrite(PIN_BUZZER, zona == BAHAYA ? HIGH : LOW);
    Serial.println(static_cast<int>(zona));
  }
}
```

Papan tiruan di bawah memakai dua fungsi yang sama. Ia menguji jarak langsung, termasuk nilai tepat di batas, lalu waktu gema karangan.

```cpp
// C++17 biasa, jalan di komputer. Diperiksa oleh check:module-code.
#include <iomanip>
#include <iostream>

const float CM_PER_US = 0.0343f;        // contoh: suara kira-kira 343 m/s; bergantung suhu udara
const float JARAK_MIN_CM = 2.0f;        // contoh; periksa lembar data sensormu
const float JARAK_MAKS_CM = 400.0f;     // contoh; periksa lembar data sensormu
const float BATAS_BAHAYA_CM = 20.0f;    // ukur sendiri; ini contoh
const float BATAS_WASPADA_CM = 50.0f;   // ukur sendiri; ini contoh

enum Zona { TIDAK_VALID, AMAN, WASPADA, BAHAYA };
const char* NAMA[] = {"TIDAK_VALID", "AMAN", "WASPADA", "BAHAYA"};

// Waktu gema adalah waktu pergi-pulang, jadi jaraknya dibagi 2.
float cmDariMikrodetik(unsigned long mikrodetik) {
  return mikrodetik * CM_PER_US / 2.0f;
}

Zona zonaDari(float cm) {
  if (cm < JARAK_MIN_CM || cm > JARAK_MAKS_CM) {
    return TIDAK_VALID;
  }
  if (cm < BATAS_BAHAYA_CM) {
    return BAHAYA;
  }
  if (cm < BATAS_WASPADA_CM) {
    return WASPADA;
  }
  return AMAN;
}

int main() {
  std::cout << std::fixed << std::setprecision(1);
  const float CM[] = {1.5f, 19.9f, 20.0f, 49.9f, 50.0f, 450.0f};
  for (float cm : CM) {
    std::cout << cm << " cm -> " << NAMA[zonaDari(cm)] << "\n";
  }
  const unsigned long WAKTU_US[] = {0, 580, 2915, 5830};
  for (unsigned long us : WAKTU_US) {
    float cm = cmDariMikrodetik(us);
    std::cout << us << " us -> " << cm << " cm -> " << NAMA[zonaDari(cm)] << "\n";
  }
}
```

Keluarannya:

```text
1.5 cm -> TIDAK_VALID
19.9 cm -> BAHAYA
20.0 cm -> WASPADA
49.9 cm -> WASPADA
50.0 cm -> AMAN
450.0 cm -> TIDAK_VALID
0 us -> 0.0 cm -> TIDAK_VALID
580 us -> 9.9 cm -> BAHAYA
2915 us -> 50.0 cm -> WASPADA
5830 us -> 100.0 cm -> AMAN
```

Perhatikan baris `2915 us`: jaraknya 49,99 cm, ditampilkan 50,0 karena pembulatan, tetapi keputusannya memakai angka sebenarnya sehingga zonanya `WASPADA`. Angka yang ditampilkan bukan angka yang diputuskan. Baris `0 us` menggambarkan "tidak ada gema" pada papan tiruan. Di lapangan, keputusan lebih aman diambil dari median beberapa pembacaan (`c-x2-m10`) daripada dari satu pembacaan.

## Kesalahan umum

- **Lupa membagi dua.** Jarak yang dihitung dua kali lipat dari kenyataan, karena waktu gema mencakup pergi dan pulang.
- **Menganggap "tidak ada gema" sebagai jarak 0.** Alarm berbunyi tanpa benda sama sekali.
- **Memutuskan dari satu pembacaan.** Satu pembacaan palsu langsung menyalakan atau mematikan alarm; median beberapa pembacaan lebih stabil.
- **Menebak batas.** Batas yang tepat bergantung pada sensor, ruangan, dan benda; ukur dengan penggaris.
- **Mengira angka yang ditampilkan sama dengan angka yang diputuskan.** Pembulatan tampilan dapat menyembunyikan bahwa nilainya masih di bawah batas.

## Kunci dan petunjuk

**Ingat kembali.** 1: median (5), karena rata-rata (23,6) ditarik oleh 100. 2: 30 x 20 / 40 = 15. 3: bandingkan dengan alat acuan seperti penggaris; dua pengamat mencatat sendiri-sendiri lalu mencocokkan. 4: `7 / 2` memberi 3 (pembagian bilangan bulat membuang sisa); `7.0 / 2` memberi 3,5 karena salah satu operan berkoma.

**Prediksi dulu.** 1: 12 cm `BAHAYA`; 20 cm `WASPADA` (karena `cm < 20` salah pada tepat 20); 49 cm `WASPADA`; 500 cm `TIDAK_VALID`. 2: 1166 x 0,0343 / 2 = 19,997, ditampilkan 20,0 tetapi `BAHAYA` karena 19,997 kurang dari 20. 3: tepat di batas, pembulatan dan tanda `<` atau `<=` menentukan zona; itu sebabnya nilai batas diuji.

**Contoh setengah jadi.** Isian berurutan: `2.0f`, `JARAK_MAKS_CM`, `BATAS_BAHAYA_CM`. Program lengkapnya dikompilasi penulis dengan `Arduino.h` tiruan dan header tiruan `PustakaJarak.h` tanpa peringatan.

**Soal Parsons.** Urutan benar: b, f, e, c, a, d. Pemeriksaan `TIDAK_VALID` harus pertama; `BAHAYA` harus sebelum `WASPADA`, karena 15 cm juga lebih kecil dari 50.

**Latihan.** 1: pseudocode: ULANG tiap 100 ms: baca waktu gema; BILA gagal, zona tidak valid; JIKA TIDAK, ubah ke cm lalu tentukan zona; buzzer nyala hanya di BAHAYA; LED nyala di WASPADA dan BAHAYA. 2: 3500 x 0,0343 / 2 = 60,0 cm, `AMAN`; 700 x 0,0343 / 2 = 12,0 cm, `BAHAYA`. 3: `waktu` 0 menjadi jarak 0 cm, kurang dari batas bahaya, sehingga alarm berbunyi tanpa benda; padahal 0 berarti tidak ada gema, bukan jarak 0. Perbaikan: periksa nilai kembalian dan rentang valid. 4: tidak ada kunci tunggal; jawaban yang baik menyebut sebaran pembacaan tiap jarak dan memilih batas di luar sebaran itu.

**Latihan bercampur.** 1: rata-rata = (52 + 53 + 3 + 52 + 51) / 5 = 42,2 cm, `WASPADA`; median (terurut 3, 51, 52, 52, 53) = 52 cm, `AMAN`. Satu pembacaan palsu menggeser rata-rata ke zona yang salah. 2: `millis() - mulai >= 100`, lalu `mulai = millis();`.

**Ulang berjarak.** 1: karena itu tanda gagal membaca, bukan hasil ukur; mengubahnya menjadi jarak membuat keputusan didasarkan pada angka palsu. 2: karena waktu gema adalah perjalanan pergi dan pulang, sedangkan jarak benda hanya satu arah. 3: alarm bergantian menyala dan padam cepat, mengganggu dan sulit dipercaya; ini salah satu alasan keputusan dengan satu ambang perlu dikembangkan di kelas XI.
